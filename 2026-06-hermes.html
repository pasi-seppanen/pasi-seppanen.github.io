How Hermes became a morning report on a Helsinki VPS

June 20266 min readTechnology

Today I wrapped the Hermes auto-trader experiment into a usable, repeatable setup. This is the story of the day I took a Claude-driven agent, a paper-trading strategy, and a hardened VPS and made them work together on a schedule.

"An autonomy experiment: a self-hosted Hermes Agent running a deterministic momentum paper-trading strategy on a virtual 300 USDT budget, controlled via Telegram, on a hardened VPS. Goal was 'can an agent run a real strategy on its own?' — yes; it now trades on a schedule and reports each morning."

What I built

The project is not just code. It is the environment, the safety fences, and the way the agent is allowed to act. The technical stack today looks like this:

  • Host: Hetzner Cloud CPX32 in Helsinki, Ubuntu 26.04 LTS, user hermes, SSH key-only access.
  • Hardening: ufw open only to OpenSSH, fail2ban running, unattended-upgrades enabled.
  • Tool runtime: Docker with nikolaik/python-nodejs:python3.11-nodejs20, the Hermes skill runs in a container, not on the host.
  • Agent: Hermes installed under ~/.hermes, managed by the user systemd service hermes-gateway with linger enabled so it survives logout and reboot.
  • Model: GPT-5.5 via OpenAI Codex OAuth, using my ChatGPT Pro account rather than a raw API key.
  • Channel: Telegram bot “James” (@HermesAgentForUs_bot), locked to my personal Telegram user and a private home channel.

The actual trade guardrail

Most of the work was not writing the strategy. It was deciding what the agent is allowed to do.

"The agent (James) is READ-ONLY re: trading — on request it runs status/report. It must never run trade.py run (the cron owns trading)."

That line is the core of the experiment. James can answer questions, summarize position state, and explain the strategy. The live execution path is separate and deterministic.

The auto-trader itself

The trading skill lives under ~/.hermes/skills/finance/auto-trader, with local source of truth in hermes-auto-trader/. The strategy is simple, explicit and paper-only:

  • Universe: top 20 USDT pairs by 24h volume, excluding stablecoins and leveraged tokens.
  • BUY after 2 consecutive higher 15-minute rounds, position size = 20% of available cash.
  • ADD when a held coin goes green again, using another 20% of free cash.
  • SELL the whole position after one red 15-minute round.
  • Budget: 300 USDT; daily loss cutoff 30 USDT (buys stop, sells still happen).

The simulation uses real Binance market data and a 0.1%/side fee model. It is a realistic experiment without real money on the line.

Automation and the morning report

Once the trading logic was in place, the next step was the schedule:

  • autotrader-run every 15 minutes runs ~/.hermes/scripts/autotrader-run.sh and ticks the strategy.
  • autotrader-morning at 05:05 UTC (08:05 Helsinki in summer) runs ~/.hermes/scripts/autotrader-morning.sh, which in turn runs trade.py report and delivers the result to Telegram.

That hook turned the project from an experiment into a daily habit. Every morning, James sends me a readout I can actually use.

What is still unfinished

This is an autonomy experiment, not a deployed fund.

"Going live is NOT a config flip. MODE=live is intentionally stubbed in trade.py (raises an error). Real trading needs the live signed-order execution path built + tested, a real funded account, and a trade-only, withdrawals-OFF Binance key."
  • Fix DST for Finland: change the morning job to 06:05 UTC once summer time ends.
  • Build a plot script around equity_log.jsonl once there is a week of data.
  • Keep the live path separated, with sensible caps and a conservative risk profile if I ever move from paper to real.

Why this felt like progress

Most writing about AI agents focuses on the model. This one felt different because the useful part is the wiring: the host, the container, the service, the Telegram channel, the cron schedule, and the guardrails.

It is still an experiment, but it now has a clear narrative: the agent is not the trader, the agent is the assistant that watches, reports, and keeps the system honest.
